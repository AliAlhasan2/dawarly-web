# دورلي — Dawarly 🏠

منصة عقارات سورية على الويب بتصميم عربي عصري ومتجاوب، مبنية بـ **Next.js 15 + React 19 + Supabase**.

## ما الموجود داخل المشروع؟

- ✅ صفحة رئيسية عصرية ومتجاوبة RTL.
- ✅ صفحة تصفح، بحث بالمحافظة، الحي، البيع/الإيجار والسعر **بالدولار**.
- ✅ صفحة تفاصيل العقار والصور والمواصفات والتواصل بالهاتف وواتساب.
- ✅ مفضلة محلية بالمتصفح (بدون مزامنة بين الأجهزة).
- ✅ تسجيل، دخول، تأكيد بريد، استعادة كلمة مرور عبر Supabase.
- ✅ لوحة معلن تعرض عقاراته مع تعديل وحذف.
- ✅ إضافة عقار ورفع صور (حتى 8 صور، 5 ميغابايت لكل صورة).
- ✅ انتظار المراجعة قبل نشر الإعلانات.
- ✅ لوحة إدارة محمية بواسطة جدول admin_users وسياسات قاعدة البيانات.
- ✅ قواعد وصول RLS وسياسات تخزين الملفات.
- ✅ وضع عرض تجريبي ببيانات *وهمية واضحة* قبل ربط قاعدة البيانات.

> **مهم:** المجلد الجاهز يحتوي على الشيفرة، وليس موقعاً مفعّلاً على استضافة عامة. لتفعيله يلزم حساب Supabase ونشر على Vercel واختيار دومين. الصور الظاهرة في وضع العرض صور خارجية توضيحية من Unsplash وليست لعقارات فعلية.

## 1. التجهيز

ثبّت [Node.js LTS](https://nodejs.org/) (نسخة 20 أو أحدث) و[VS Code](https://code.visualstudio.com/).

افتح Terminal داخل المجلد:

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:3000`.

**بدون مفاتيح Supabase:** يمكنك تصفح التصميم ببيانات تجريبية؛ لن تعمل الحسابات أو حفظ الإعلانات قبل الربط.

## 2. تجهيز Supabase

1. ادخل [Supabase Dashboard](https://supabase.com/dashboard) وأنشئ مشروعاً جديداً.
2. افتح **SQL Editor** وشغّل محتوى الملف `supabase/schema.sql` كاملاً في مشروع جديد.
3. تأكد أن **Storage → property-images** ظهر. SQL ينشئه آلياً.
4. من Project Connect / API Keys خذ **Project URL** و**publishable (أو anon) key**.
5. انسخ `.env.example` إلى `.env.local` وضع القيم الصحيحة:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

6. أعد تشغيل `npm run dev` بعد تغيير ملف البيئة.
7. افتح **Authentication → URL Configuration** واضبط Site URL حسب عنوان الموقع الفعلي بعد النشر. أضف Redirect URLs التالية أثناء التطوير:
   - `http://localhost:3000/login`
   - `http://localhost:3000/reset-password`
   - `https://YOUR-DOMAIN.com/login`
   - `https://YOUR-DOMAIN.com/reset-password`
8. فعّل البريد الإلكتروني في **Authentication → Providers**، واضبط SMTP حقيقي قبل الإطلاق للعامة حتى تصل رسائل التأكيد والاستعادة reliably.

**مفاتيح مهمة:** لا تستخدم أبداً `service_role` أو `secret` داخل متغيرات `NEXT_PUBLIC_*` أو GitHub. المشروع يعمل بسياسات RLS مع مفتاح عام.

## 3. إنشاء أول مستخدم مدير

1. افتح `/login` وسجّل حساب مستخدم، ثم أكّد بريده إن كان التأكيد مفعلاً.
2. من Supabase → Authentication → Users انسخ **User UID** لذلك المستخدم.
3. في SQL Editor نفّذ هذا الأمر **يدوياً من لوحة Supabase** بعد تبديل المعرف:

```sql
insert into public.admin_users (id)
values ('ACTUAL-USER-UUID');
```

4. افتح `/dashboard` وسيظهر زر **لوحة الإدارة**؛ منها راجع المنشورات ووافق عليها أو ارفضها.

> لا تضع رقم المدير في ملفات الموقع، ولا تعطي دور المدير بناءً على قيمة يمكن للمستخدم تغييرها في المتصفح.

## 4. إضافة أول عقار

1. سجّل الدخول.
2. افتح **أضف عقارك** من أعلى الموقع أو `/dashboard/new`.
3. أضف العنوان والمنطقة والسعر، وصفاً من 20 حرفاً على الأقل، وصورة واحدة على الأقل، وبيانات تواصل صحيحة.
4. عند الحفظ سيظهر الإعلان في لوحة المعلن بحالة **بانتظار المراجعة**.
5. سجّل دخولك كمدير من الحساب المحدد أعلاه، افتح `/admin` واضغط **موافقة**.
6. يظهر العقار حالاً في `/properties` ويصبح له رابط عام.
7. عند تعديل عقار منشور يعود إلى مرحلة المراجعة ولا يعود للظهور حتى يوافق عليه المدير.

## 5. رفع المشروع ونشره

### GitHub

أنشئ مستودعاً ثم شغّل:

```bash
git init
git add .
git commit -m "Dawarly first release"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/dawarly-web.git
git push -u origin main
```

تأكد أن `.env.local` ليس ضمن الملفات المحفوظة في Git؛ ملف `.gitignore` مجهز لذلك.

### Vercel

1. ادخل [Vercel](https://vercel.com/) وسجّل الدخول باستخدام GitHub.
2. اختار **Add New → Project** ثم مستودع `dawarly-web`.
3. أضف متغيرات البيئة الثلاثة الموجودة في `.env.local` ضمن إعدادات المشروع (استخدم رابط الموقع الفعلي لـ `NEXT_PUBLIC_SITE_URL`).
4. اضغط Deploy. ستستلم رابطاً من Vercel بعد نجاح البناء.
5. اربط دومين من **Settings → Domains** ثم اتبع إعداد DNS المعروض.
6. ارجع لـ Supabase وأضف رابط الإنتاج إلى **URL Configuration**.

## 6. حماية قبل الإطلاق

- قاعدة البيانات تستخدم RLS؛ لا توقفها في جداول المشروع.
- مسارات الصور تخضع لصلاحيات المالك والأنواع والحجم المسموح.
- الصور مخزنة في bucket **عام**؛ لا ترفع هويات أو وثائق خاصة.
- المشرف يراجع الإعلان قبل النشر، لكن هذا **ليس تحققاً قانونياً من الملكية**.
- المعلن مسؤول عن موافقته على عرض أرقام التواصل.
- نموذج الخصوصية أولي ويحتاج مراجعة قانونية وتحديد وسيلة للتواصل قبل الإطلاق التجاري.
- استخدم نسخاً احتياطية واستراتيجية مكافحة البريد المزعج قبل التوسع.
- لو أردت رفع مستندات حساسة، استخدم تخزيناً خاصاً مع آلية وصول منفصلة.
- تقييد تعديل حقول العقار يجري عبر RLS، مع حالة `pending` عند تعديل المعلن؛ على المشرف التأكد من المحتوى.
- حذّر المستخدمين من دفع عربون دون تحقق مستقل.

## 7. حدود النسخة الأولى

هذه نسخة MVP حقيقية وليست نظام وساطة عقارية متكامل. لا تشمل: دفع إلكتروني، دردشة مدمجة، تحقق من الوثائق، خرائط فعلية، دعم متعدد اللغات، تحليلات متقدمة، أو مطابقة بالذكاء الاصطناعي. المفضلة تُحفظ محلياً فقط. فلتر الحد الأقصى للسعر يخص عقارات USD ولا يحول الليرة السورية لسعر صرف لحظي. تحميل النتائج محدود إلى 12 إعلاناً بالصفحة.

## 8. بنية الملفات

```
app/                 صفحات Next.js
components/          مكونات الواجهات والعمليات
lib/                 إعداد Supabase، الأنواع، وبيانات العرض
supabase/schema.sql  الجداول وسياسات الحماية والتخزين
.env.example         نموذج متغيرات البيئة
middleware.ts        تجديد جلسات Supabase
```

## 9. اختبار البناء

```bash
npm run build
npm run start
```

إذا استخدمت نسخاً أحدث من المكتبات وكانت هناك تغييرات في واجهات API، ثبت النسخ المعرّفة في `package.json` وتأكد من نتائج `npm run build` قبل نشر الإنتاج.
